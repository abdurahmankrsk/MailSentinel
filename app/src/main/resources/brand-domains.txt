# MailSentinel watched brands.
#
# One brand per line. The FIRST domain is the brand's primary domain; every domain
# after it on the same line is another domain that brand legitimately sends from.
# Blank lines and lines starting with # are ignored. Order is significant and stable:
# when several brands match, the first one listed is the one named in the finding.
#
# The primary domain is what user-facing messages name ("the real domain is
# amazon.com") and what edit-distance compares against. Regional variants exist so a
# genuine amazon.co.uk email is recognised as Amazon rather than as a typosquat of it.
#
# ---------------------------------------------------------------------------------
# TWO RULES FOR EDITING THIS FILE
#
# 1. Listing a domain asserts it is SAFE. A missing regional domain costs a false
#    positive; a wrongly included one silently allowlists a phishing domain. When in
#    doubt, leave it out and add it when a false positive is actually reported.
#
# 2. Prefer primary labels of 5+ characters that are not ordinary English words.
#    Edit-distance matching compares whole domains, so a short primary generates
#    false positives against unrelated sites: "ing.com" would flag inc.com and
#    img.com as lookalikes of ING. The three short entries below (ups, irs, fb)
#    predate this rule and are kept because they are heavily phished; do not add
#    more without a specific reason.
#
# Brands whose label is an ordinary English word are additionally listed in
# BrandConstants.COMMON_WORD_BRAND_LABELS, which requires corroboration before the
# brand-in-domain technique will fire on them. See that constant for why.
# ---------------------------------------------------------------------------------
